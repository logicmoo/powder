# Authenticated local Prolog debug console

This service runs queries **inside the existing app process and its loaded KB**.
It does not start another SWI interpreter, inspect an unrelated catalog daemon,
or resurrect the exited external process 68040.

## Deployment contract — disabled until explicitly started

Importing `prolog\ow_dr\kb_debug_telnet.pl` starts nothing. Parent-owned app
integration may load just this module through an authorized code-load mechanism,
then invoke:

```prolog
kb_debug_telnet:start_debug_telnet([port(3051)]).
kb_debug_telnet:stop_debug_telnet.
```

Do not inject commands into P/S controls or globally reload/restart the app.
Live activation must wait for the parent's frozen handoff. No HTTP endpoint is
installed by this module. If the host adds an administration endpoint, it must
be explicitly local/typed, enforce strong exact-origin checks, and never expose
credentials or their private path in HTTP responses, catalogs, status, or logs.

For normal startup/shutdown, wrap the app's existing serving scope with
`setup_call_cleanup(start_debug_telnet(Options), ExistingScope, stop_debug_telnet)`.
The host should default its saved enable setting to **false**. Passing
`[enabled(false)]` stops the service. An unchanged start is idempotent; changing
options while running requires explicit stop then start. No settings file,
compiler fingerprint, corpus, listening HTTP port, or pool is changed here.

The TCP bind is always **127.0.0.1**, never an unspecified address. `port/1`
defaults to 3051 and accepts 1–65535; an occupied port fails without displacing
its owner. There is no address override, port fallback, or firewall change.

## Private credentials and connection

Windows is the supported server platform. Windows PowerShell/.NET creates a
new directory and file with protected, owner-only DACLs **before writing the
secret**, refuses reparse paths or existing insecure ACLs, and verifies them.
The per-user location is:

```text
%LOCALAPPDATA%\powder-local-debug\<APP_PID>-<random-id>\credentials.json
```

The secret contains 256 bits generated by SWI's cryptographic random source.
It is never a command-line option, HTTP field, startup message, or source-file
literal. Only a SHA-256 digest is retained by the running service. Every start
creates a fresh secret; normal stop removes its private file/directory. A crash
may leave an owner-private stale file; it cannot authenticate a later start.

Local trusted code may obtain **only the path** with
`kb_debug_telnet:debug_credentials_file(Path)`. Connect from a separate client
console, not the app's input scanner:

```powershell
python prolog\ow_dr\debug_telnet_client.py --pid APP_PID
python prolog\ow_dr\debug_telnet_client.py --credentials "PRIVATE_FILE_PATH"
python prolog\ow_dr\debug_telnet_client.py --pid APP_PID --probe
```

Python 3 is needed only for the bundled client/tests, not for serving. The probe
performs only `current_prolog_flag(pid, PID), thread_self(Thread).` after
authentication, then disconnects. It never starts or modifies another process.
If stale files make PID discovery ambiguous, supply the exact current path.
Never copy the token into a command line, chat, log, or debugger screenshot.

## Protocol and REPL behavior

This is a **raw TCP, Telnet-style line console**, not HTTP/JSON and not a full
Telnet terminal implementation. Use the bundled client. It sends UTF-8 and
LF/CRLF (CR-NUL is also accepted). Telnet IAC negotiation and terminal-control
bytes are rejected, not interpreted. Standard Windows Telnet clients that send
negotiation are therefore not supported. There is no history, completion,
terminal emulation, or remote Control-C promise.

The server sends `POWDER DEBUG 1` and `AUTH required`. The client's first line
must be `AUTH ` followed by the private token. Before authentication there is
**no Prolog parsing, goal execution, PID, thread, KB, or status disclosure**.
Failure produces a generic denial or closes the connection.

After `OK`, enter one complete Prolog goal per line. Goals execute in module
`user` on a dedicated thread in this same process, with that client's own I/O.
Bindings and residual constraints are printed. Enter `;` at the alternatives
prompt for another solution, or an empty line to accept the current solution.
This managed read/call/print loop intentionally does **not** invoke
`prolog_server/2`, `prolog/0`, or the configured `toplevel_goal`: SWI 10.1.7's
native toplevel can call `halt(0)` on EOF at an alternatives prompt, and this
app commonly has `toplevel_goal=halt`.

`end_of_file.` or socket EOF closes **only this client**, including while
waiting for alternatives. An incomplete final line is discarded. Syntax errors
and query exceptions are returned only to the authenticated client. Queries
that request additional interactive input are not a supported terminal
workflow: `user_input` is the underlying byte socket.

This is a **fully privileged administrator Prolog REPL**, not the application's
safe KB-query API or a sandbox. A credential holder can deliberately mutate the
KB, access files, launch processes, or call `halt/0`. No such commands run
automatically. **Never use `halt/0` to disconnect.** Local administrators or
compromised same-user processes can access process memory/credentials. Traffic
is loopback plaintext, not encrypted or protected against a privileged local
attacker. Ctrl+C in the bundled client exits that client only; an in-progress
remote goal may continue until its limit or host stop.

## Limits, cleanup, and checkpoints

Options and defaults:

| Option | Default |
|---|---:|
| `auth_timeout` | 5 seconds |
| `idle_timeout` | 300 seconds |
| `session_timeout` | 900 seconds |
| `query_timeout` | 30 seconds |
| `max_sessions` | 2, including unauthenticated connections |
| `attempt_limit` / `attempt_window` | 10 accepted authentication attempts / 60 seconds |
| `max_line` | 16384 bytes |

Authentication has its own 80-byte line cap. Query time includes the wait at
its alternatives prompt. Rate limiting is local-service-wide, so another local
user can cause temporary denial of service but cannot bypass authentication.
Timeouts close idle/authentication/session connections; ordinary query timeout
reports an error and returns to the prompt.

Host stop revokes authentication, closes the listener, signals only tracked
debug threads, and waits up to three seconds for cooperative thread cleanup.
It never halts/kills the app or touches its main input. Calling host stop from
the same debug client is rejected to avoid self-join; disconnect normally.
Deliberately exception-swallowing code or non-interruptible foreign code may
prevent timely cleanup: stop reports this honestly and retains `stopping`
ownership for retry instead of silently leaking it or force-killing a process.

All service, socket, thread, digest, and rate records are declared volatile.
The isolated checkpoint builder should call
`kb_debug_telnet:debug_snapshot_safe/0` when this module is loaded. It rejects
active/stopping service resources. Do not copy the private credential directory
into source packs or checkpoints. After restoring data, the host explicitly
starts the configured service with fresh sockets and credentials; no
initialization directive resurrects stale handles or authentication.

## Focused validation

```powershell
swipl -q -g run_tests -t halt prolog\ow_dr\tests\test_debug_telnet.pl
python prolog\ow_dr\tests\test_debug_telnet_integration.py -v
```

Tests use only isolated SWI children and ephemeral loopback ports. They verify
same-process facts/PID, rejected unauthenticated goals, real Windows private
ACLs, credential rotation/removal, main-I/O preservation, occupied ports,
limits, and client-only EOF with `toplevel_goal=halt`. No live app is enabled
or restarted by these tests.
